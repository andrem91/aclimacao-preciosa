# Projeto: Aclimação Preciosa

Quero que você desenvolva a primeira versão funcional do site **Aclimação Preciosa**, utilizando como referência visual os arquivos HTML/CSS exportados pelo Google Stitch que estão disponíveis neste projeto.

Antes de escrever código, analise todos os layouts fornecidos pelo Stitch e entenda o sistema visual existente.

Não copie os HTMLs de forma literal.

Use-os como **referência de design**, reconstruindo a interface de forma limpa, componentizada, responsiva e adequada à stack descrita abaixo.

---

# 1. Contexto do projeto

**Aclimação Preciosa** é um projeto voltado à valorização do bairro da Aclimação, em São Paulo.

O objetivo de longo prazo é ajudar a transformar o bairro de um local de passagem em um destino de:

* comércio local;
* gastronomia;
* cultura;
* lazer;
* experiências;
* eventos;
* história;
* turismo local;
* convivência.

O portal digital é uma das ferramentas dessa iniciativa.

Ele não deve parecer:

* marketplace;
* e-commerce;
* portal da prefeitura;
* guia turístico genérico;
* sistema corporativo;
* rede social.

A experiência desejada é a de um:

> **guia urbano e editorial contemporâneo para descobrir a Aclimação.**

O usuário deve sentir algo como:

> “Eu não sabia que havia tanta coisa interessante na Aclimação.”

---

# 2. Objetivo da versão v0.1

A primeira versão deve ser propositalmente simples.

Queremos colocar no ar um **MVP bonito, rápido e funcional**, que permita:

1. descobrir estabelecimentos;
2. conhecer eventos e experiências;
3. descobrir lugares interessantes;
4. abrir páginas individuais desses conteúdos;
5. mostrar informações básicas;
6. permitir que comerciantes e moradores demonstrem interesse em participar.

Não queremos construir agora toda a plataforma futura.

A prioridade da v0.1 é:

> **visual + conteúdo + navegação + simplicidade.**

# 4. Princípio técnico

A v0.1 deve ser simples, mas não desorganizada.

Os dados não devem ficar escritos diretamente dentro dos componentes React.

Criar uma separação semelhante a:

```text
src/
├── app/
├── components/
├── data/
├── lib/
├── types/
└── ...
```

Exemplo:

```text
src/data/
├── establishments.json
├── experiences.json
├── events.json
└── places.json
```

Criar tipos TypeScript correspondentes.

Criar uma camada simples de acesso aos dados, por exemplo:

```text
src/lib/
├── establishments.ts
├── experiences.ts
├── events.ts
└── places.ts
```

Exemplos de funções:

```ts
getEstablishments()
getFeaturedEstablishments()
getEstablishmentBySlug()

getEvents()
getEventBySlug()

getExperiences()
getExperienceBySlug()

getPlaces()
getFeaturedPlaces()
getPlaceBySlug()
```

Os componentes não devem ficar importando e filtrando JSON de maneira espalhada pelo projeto.

# 5. Conteúdo mockado

Nesta primeira etapa vários conteúdos ainda serão demonstrativos.

Por isso, todas as entidades devem possuir:

```ts
isMock: boolean
```

Quando:

```ts
isMock === true
```

a interface pode mostrar discretamente:

**Demonstração**

Isso é especialmente importante para:

* eventos;
* experiências;
* informações ainda não confirmadas.

Nunca apresentar conteúdo fictício como se fosse informação oficial.

---

# 6. Conteúdo real x demonstrativo

É aceitável misturar no protótipo:

### Conteúdo real

* alguns estabelecimentos;
* lugares reais;
* nome do projeto;
* textos institucionais.

### Conteúdo demonstrativo

* experiências futuras;
* eventos ainda não confirmados;
* exemplos de programação.

Sempre utilizar `isMock` para diferenciá-los.

---

# 7. Direção visual

Os HTMLs gerados pelo Stitch representam a referência visual principal.

Preservar a identidade criada:

* fundo off-white / creme claro;
* verde profundo como cor principal;
* amarelo/ocre/dourado usado pontualmente;
* tipografia serifada elegante nos títulos;
* sans-serif limpa nos textos;
* fotografia em destaque;
* bastante espaço em branco;
* aparência editorial;
* clima urbano e acolhedor;
* poucos efeitos;
* sombras discretas;
* bordas sutis;
* cantos arredondados com moderação.

O conceito visual pode ser entendido como:

> **Editorial urbano botânico.**

Também existe uma referência sutil ao conceito de algo “precioso”, mas:

* não usar diamantes grandes;
* não parecer joalheria;
* não exagerar em elementos de pedra preciosa.

Evitar modelos gigantes.

```ts

  id: string
  slug: string
```

# 39. Processo de implementação

Antes de alterar o projeto:

1. examine todos os arquivos exportados pelo Stitch;
2. identifique cores, tipografia, espaçamentos, cards e padrões;
3. identifique elementos que pertencem à versão complexa e devem ser removidos;

# 40. Princípio final

A regra principal da v0.1 é:

> **Se algo não for necessário para o usuário descobrir um estabelecimento, evento, experiência ou lugar, provavelmente não precisa existir ainda.**

Queremos lançar:

> **um guia digital bonito, simples e rápido da Aclimação.**

Não queremos construir agora:

> **uma plataforma gigantesca de turismo, comércio e comunidade.**

Faça a primeira versão muito bem feita e deixe o produto preparado para evoluir por etapas.
